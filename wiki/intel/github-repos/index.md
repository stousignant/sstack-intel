# GitHub Repo Intelligence

This is the **single cross-repo rollup** for curated GitHub repository intelligence. Individual cards own detailed evidence; comparisons explain category choices without duplicating adoption tracking.

Individual repo pages under `repos/` hold detailed evidence and scorecards. This page rolls up one row per reviewed repo. The usage values are intentionally retained as dated reference-stack relationships, not a live deployment inventory or universal quality ranking. [Awesome Harness Engineering](../awesome-harness-engineering/index.md) is a separate lightweight catalog with a distinct rubric; it does not replace the deep-card decision surface.

Dated evidence and workload preferences are retained under the [evaluation methodology](../awesome-harness-engineering/methodology.md); this is not a freshness recheck.

This rollup preserves historical recommendation, usage and review-date snapshots rather than claiming full synchronization with the detailed cards. Three score corrections were made against the pinned source-card values: Spec Kit 92→86, agent-scripts 92→90 and OpenSpec 86→84. Later dated card judgments can differ; use the linked cards for their subsequent review evidence. Historical adopt-now and not-used values are not present adoption/runtime facts.

## Canonical fields

| Field | Meaning |
|---|---|
| `usefulness_score` | 0–100 score for reference-stack usefulness, not generic GitHub quality. Lightweight migrated notes use provisional low-confidence scores. |
| `recommendation` | Next recommendation: `adopt-now`, `distill-pattern`, `watch`, `reference-only`, `defer`, or `reject`. |
| `usage` | Dated reference-stack relationship: `active-runtime`, `active-index-layer`, `pattern-in-use`, `sandboxed`, `reference-only`, or `not-used`. |
| `score_confidence` | Confidence in the score: `high`, `medium`, or `low`. |

## Score rubric

| Factor | Points | What it captures |
|---|---:|---|
| Stack fit | 25 | Fit with the disclosed Hermes/GBrain/Markdown-vault/local-first workflows. |
| Leverage | 25 | Time saved, autonomy gained, optionality/income support. |
| Reuse readiness | 20 | Installability, docs, examples, integration cost. |
| Maturity/trust | 15 | Maintenance, tests, license, security posture. |
| Differentiation | 15 | Better than current stack/alternatives, or a unique pattern worth keeping. |

## Evidence tiers

| Tier | Meaning | Evidence expectation |
|---|---|---|
| Tier 0 — raw capture | Metadata/source capture only | No adoption inference |
| Tier 1 — lightweight triage | Short provisional assessment | Low confidence; explicit refresh trigger |
| Tier 2 — category comparison | Several repos in one theme | Comparative reasoning; canonical per-repo dispositions remain in this rollup |
| Tier 3 — deep analysis | 3–5 survivors | Dated metadata, README/docs, license, maintenance/security evidence, and bounded smoke tests when safe |

Bulk discovery does not justify bulk adoption. Executable commitments belong to the existing work owner; reusable intelligence remains source-backed and non-binding.
