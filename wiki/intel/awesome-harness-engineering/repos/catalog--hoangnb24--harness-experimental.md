# hoangnb24/harness-experimental
## Quick take
repository-harness is a repository protocol for making authority, decisions, plans, and completion evidence legible to coding agents.
## Score
**86/100**
- **Harness relevance — 28/30:** Installs a repository-level operating protocol, agent entrypoint, plans, decision boundaries, and validation structure.
- **Practical pattern value — 23/25:** Authority maps, bounded-change rules, durable plans, ambiguity gates, safe updates, and proof requirements transfer directly.
- **Evidence and maturity — 16/20:** The active MIT successor documents checks, release evidence, installers, maintenance, and explicit scope limits.
- **Novelty — 11/15:** Treats repository legibility and evidence boundaries as the harness while deliberately excluding orchestration.
- **Risk-adjusted accessibility — 8/10:** Dry-run and merge modes help, but bootstrap installers write governance files into a target repository.
## Why it matters
- It draws a useful boundary between repository governance and runtime orchestration.
- Its stop-on-material-ambiguity and behavior-proof rules encode common safeguards for long-running agent work.
