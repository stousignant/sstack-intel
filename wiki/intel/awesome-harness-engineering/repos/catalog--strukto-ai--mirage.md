# strukto-ai/mirage
## Quick take
Mirage gives agents a permissioned virtual terminal spanning data sources, service CLIs, and routed runtimes.
## Score
**79/100**
- **Harness relevance — 20/30:** Virtual files, commands, runtimes, permissions, and credentials form a substantial agent execution and context layer.
- **Practical pattern value — 23/25:** Mount-based data access, typed virtual CLIs, runtime routing, and scoped permissions are directly reusable patterns.
- **Evidence and maturity — 14/20:** The active project has detailed documentation, multiple SDKs, and Apache-2.0 licensing.
- **Novelty — 15/15:** Presenting heterogeneous services and runtimes as one permissioned virtual terminal is unusually differentiated.
- **Risk-adjusted accessibility — 7/10:** Permissive licensing and SDK quickstarts help, while external services, credentials, and routed execution require care.
## Why it matters
- Unifies heterogeneous data behind filesystem semantics that standard Unix-style tools can traverse.
- Decouples commands from execution runtimes while controlling what agents can see and do.
## Caveat
Security, cost, and token-efficiency claims are README-level, and useful evaluation requires real service and credential integrations.
