# mex-memory/mex
## Quick take
A repository-native team-memory system that separates durable reviewed knowledge from local retrieval indexes.
## Score
**82/100**
- **Harness relevance — 20/30:** Repository-backed memory, retrieval, grounding, and handoffs are substantial harness state components.
- **Practical pattern value — 23/25:** Canonical Markdown, local rebuildable indexes, drift signals, and explicit write previews are directly reusable.
- **Evidence and maturity — 18/20:** The active v0.8 project documents CI, releases, security boundaries, compatibility, and detailed workflows under MIT.
- **Novelty — 13/15:** It combines Git-shared team memory with local code graphs, governed proposals, signed previews, and durable relays.
- **Risk-adjusted accessibility — 8/10:** MIT and npx help, though Node 22.5, repository writes, indexes, and setup review add friction.
## Why it matters
- Offers strong patterns for canonical-versus-derived memory, grounding drift, and explicit mutation approval.
- Preserves cross-session and cross-person handoffs as reviewable Git artifacts.
## Caveat
MEX is not an authorization or synchronization service, and its setup writes project files that must be reviewed before commit.
