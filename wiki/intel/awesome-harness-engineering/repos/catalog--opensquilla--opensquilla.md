# opensquilla/opensquilla
## Quick take
A microkernel agent runtime using local complexity routing to share one tool, retry, memory, and decision loop across interfaces.
## Score
**89/100**
- **Harness relevance — 30/30:** Implements a full agent runtime spanning routing, memory, tools, sandboxing, channels, CLI, and web UI.
- **Practical pattern value — 23/25:** A shared turn loop, local complexity router, provider fallback, layered sandbox, and operator controls are transferable.
- **Evidence and maturity — 16/20:** The active Apache-2.0 project documents a stable release, CI, installers, privacy behavior, benchmarks, and migrations.
- **Novelty — 14/15:** On-device complexity routing tied to adaptive prompts and one microkernel loop across channels is highly differentiated.
- **Risk-adjusted accessibility — 6/10:** Release installers exist, but native dependencies, telemetry, many providers, and an unsigned Windows artifact add risk.
## Why it matters
- Shows how an on-device router can select cost tiers and scale reasoning and prompts per turn.
- Keeps CLI, web, and chat channels on a common provider, sandbox, memory, and observability path.
